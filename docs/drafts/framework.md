# Схема vs Фреймворк

## JSON Schema это спецификация + экосистема библиотек

Сам стандарт (draft 2020-12) это только спецификация: документ, описывающий синтаксис и семантику. Он не выполняет никакого кода. Чтобы что-то заработало, нужно взять библиотеку-реализацию (ajv, jsonschema, jsonschema-rs) и самому написать всё вокруг: как подавать данные, как интерпретировать результат, как разбивать на уровни серьёзности, как строить HTTP-сервис.

Аналогия: SQL это спецификация. PostgreSQL это реализация. Но даже с PostgreSQL тебе нужно самому проектировать схему, писать запросы, строить API поверх.

## JSONSpecs это фреймворк

У него есть все признаки фреймворка в классическом смысле:

- Инверсия контроля - ты не вызываешь движок, ты пишешь правила, а движок сам решает в каком порядке их выполнять
- Готовая точка расширения. Добавить новый оператор означает положить файл в lib/operators/check/ и он автоматически подхватывается компилятором
- Встроенные соглашения по структуре папок, нейминг id, видимость через library/ vs pipelines/ это не просто код, это архитектурные решения, которые навязывают определённый способ работы
- Жизненный цикл из коробки: компиляция, снэпшот, hot-reload, HTTP-сервер, трейс - всё это уже есть
- Целевая аудитория не разработчик. Аналитик пишет правила не зная ЯП. Это ключевой признак фреймворка, а не библиотеки

## Предел формулировки

Одна оговорка: слово "фреймворк" обычно подразумевает что он общего назначения и переиспользуется в разных доменах. Текущий движок пока заточен под конкретный домен (валидация банковских профилей), а операторы valid_inn, valid_ogrn это не универсальные примитивы.

Если движок обобщить и вынести доменные операторы в отдельный пакет, сделать механизм подключения внешних operator-пакетов, то он станет полноценным фреймворком общего назначения. Сейчас он ближе к предметно-ориентированному фреймворку (domain-specific framework), что для банковского контекста может быть достоинством, а не недостатком.

## Итоговая формулировка для коммуникации с командой или заказчиком:

- JSON Schema это язык описания структуры данных и набор библиотек-валидаторов. Чтобы получить рабочее решение, нужно проектировать и строить всё вокруг самостоятельно.
- JSONSpecs это фреймворк: он определяет как писать правила, как их компилировать, исполнять и версионировать. Разработчик расширяет фреймворк, аналитик работает внутри его соглашений.
